## Gold 점수 해석 주의

과거 reports/의 88/89점은 이번 수정본을 평가한 결과가 아닙니다.
원본 평가기는 숫자 부분일치(예: 50과 150), 출처 단어만으로 인용 인정,
상품 사용을 PostgreSQL 사용으로 간주하는 문제가 있었습니다.

수정한 gold100_evaluator.py는 v2입니다. 과거 코드는 gold100_evaluator_v1.py로
바이트 그대로 보존했습니다. 임계값은 낮추지 않았지만 숫자/출처 판정이 바뀌었으므로
이전 89점·0.588 coverage와 v2 결과를 그대로 대조하면 안 됩니다.
같은 v2 코드·문항·원천 데이터를 고정한 2회 평가로 새 기준선을 만들어야 합니다.
과거와 엄밀히 비교하려면 과거 답변도 같은 v2 평가기로 재채점해야 합니다.

compact composition의 사실 목록/수치/인용문 절단을 일부 제거하고 숫자만 있는
문단을 삭제하던 후처리를 없앴습니다. 그러나 coverage가 실제로 복원됐다는
주장은 라이브 결과가 없으므로 하지 않습니다. 긴 근거가 모델 토큰 예산을
넘거나 수치 반복 설명이 보수적 검증에 걸릴 위험은 여전히 있습니다.

## 유지/제외 및 잔여 위험

- 상품 JSON, 문서 청크, 법령 DB는 원본 그대로 유지했습니다. 새로운 IRP 적격성
  근거를 만들어 넣거나 기존 평가 답변을 서비스 답변에 하드코딩하지 않았습니다.
- 과거 reports/는 비교 기록으로 ZIP에 유지하지만 Docker 이미지에서는 제외합니다.
- Git 이력, 가상환경, Python 캐시, pytest 캐시, 실제 환경/키 파일은 새 ZIP에서 제외합니다.
  원본에서 삭제하지 않았으므로 원본 ZIP으로 복구할 수 있습니다.
- 의심 키를 사용하지 않았고 폐기/재발급도 하지 않았습니다. 재배포 전 소유자 확인이 필요합니다.
- 법령 날짜 필터는 최신 데이터 수집을 대신하지 않습니다. 현재 스냅샷 범위와
  동기화 스크립트의 정책값 추출 규칙을 운영자가 검증해야 합니다.
- 상품/문서 검색기는 메모리에 적재되므로 파일 교체 후 서버 재시작이 필요합니다.
- 숫자 존재/단위 검사만으로 숫자가 올바른 상품·조항에 귀속됐는지까지 보장하지 않습니다.
  의미·대상·조건 일치는 별도의 골드/홀드아웃 검증이 필요합니다.
- HyperCLOVA 기본 HTTP 타임아웃은 45초로 줄였지만 전체 요청의 엄격한
  벽시계 제한이나 고동시성 부하까지 검증한 것은 아닙니다.
- /answer의 필드 타입과 추가 필드 허용은 공식 규격 원문과 최종 대조해야 합니다.
- system_error 0, Test 12/29/30 복구, coverage 목표 달성, 92점 이상은 미확정입니다.
